## Explicación al Ing. Pacheco — Tecnologías Web II

```text
Búsqueda en el navegador
  → página Next.js recibe q/cursor
  → petición del servidor a NestJS /api/v1/courses
  → DTO valida consulta
  → servicio de catálogo selecciona registros publicados en PostgreSQL
  → contrato JSON público
  → validación de respuesta y renderizado en Next.js
```

- **Frontend:** Next.js/React/TypeScript; rutas, formularios GET, estados de carga/error/vacío y navegación adaptable.
- **Backend:** NestJS por dominios; validación de entrada, decisión de visibilidad, errores estables y OpenAPI.
- **Persistencia:** PostgreSQL conserva relaciones y restricciones. Se utiliza el esquema existente; la web no recibe credenciales de base de datos.
- **Redis:** conexión y comprobación de salud disponibles. Colas y caché de negocio aún no implementadas.
- **Monorepo:** pnpm enlaza `@esapiens/contracts`; Turborepo coordina tareas y CI ejecuta comprobaciones reproducibles.
- **Pruebas:** mostrar `pnpm test:e2e` y los casos que impiden exponer borradores, fichas privadas y contenido de lecciones. Las fixtures se revierten con una transacción.

Mostrar Swagger y una respuesta real de `GET /api/v1/courses?limit=1`; usar su `nextCursor` para explicar paginación. Explicar por qué el monolito modular reduce operaciones para un único desarrollador y permite crecer por módulos.
